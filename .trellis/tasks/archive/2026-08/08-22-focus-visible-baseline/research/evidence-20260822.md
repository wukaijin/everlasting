# 证据：键盘焦点可见性现状（2026-08-22 实测）

## 核验数据

```
focus-visible 覆盖:      grep -rln "focus-visible" --include="*.vue"  → 4 文件
含 <button 文件:          grep -rln "<button"     --include="*.vue"  → 69 文件
outline: none 声明:       grep -rn "outline:\s*(none|0)"             → 35 处
--shadow-ring 消费者:     ChatInput / MessageItemEdit / AuditLogModal / PairingView
z-index 散值:            21 个不同值(2,5,10,20,50,60,70,100,105,110,
                         200,999,1000,1100,1200,2000,2001,3000,5500,9999)
spinner keyframes:        ~10 文件(此前 Explore 子代理报 27 有夸大,以此为准)
```

## outline: none 分布（治理清单的输入）

ProjectTabs(1) / SearchModal(3) / MessageActionsMenu(2) /
RemoteTab(1) / GroupChatConfigModal(3) + 其余散点，全量清单以
`grep -rn "outline:\s*none" app/src --include="*.vue"` 实时结果为准
（实现时重新生成并逐条归类 R3 a/b/c）。

注意：`outline: none` 本身不必然是错——配了等价替代（底色高亮、
边框变色）的压制是合法的。本任务要消灭的是"压制且无替代"。

## 已有焦点样式的组件（回归对照基线）

- ChatInput.vue：`--shadow-ring` 挂在 focus-within（输入框主焦点态）
- MessageItemEdit.vue：编辑框焦点环
- AuditLogModal.vue / PairingView.vue：表单控件焦点环
- MemoryPreview / SearchModal / MessageImages / MessageActionsMenu：
  仅有的 4 处 `:focus-visible`

全局基线上线后这些组件的视觉必须不变——`:where()` 零特异性包裹 +
组件规则天然胜出的设计即为此。

## 与后续任务的关系

- **Button 组件任务**：本任务的全局环是其安全网；届时逐文件替换时
  只需处理"想要定制焦点呈现"的场景（用 opt-out 类）。
- **z-index 任务**：21 个散值清单已在上方，可直接作为该任务 research。
- **Spinner/Skeleton 任务**：实测 ~10 文件含 spin keyframes（非 27），
  该任务以自己的 re-audit 为准。

## 实施后验证（2026-08-23）

- **键盘遍历**：headless Chromium 从 body 连按 Tab 14 步,14/14 落点
  `matches(":focus-visible")=true` 且 computed `box-shadow` = 环
  （`out/ui-review/20260823-kb-focus/kb-stops.json`,含 header 按钮 /
  项目 tab / tab 关闭钮 / hidden-menu 触发器 / sidebar 操作钮 /
  会话分组折叠头）。特写截图 `22-kb-focus-closeup.png`(2x)。
- **既有焦点零回归**：ChatInput 容器 focus-within 环实测仍为
  `accent 20% / 3px`;4 个自有 :focus-visible 组件经特异性天然胜出,
  其中 SearchModal 行 / MessageImages 图 / MemoryPreview 可点块三处
  已加 `.no-focus-ring` 保持原视觉。
- **outline:none 治理结果**：35 → 26 处(删 9 处冗余:MessageActionsMenu×2、
  AuditLog trigger+option、GroupChatConfig option、SubagentsTab option、
  ProvidersTab option、ModelForm option、RuntimeMemory option);
  其余 26 处均有单行注释标注替代方案(MemoryModal/SettingsModal 原有
  块注释已覆盖)。
- **环强度观察(R4)**：accent 20% 在最暗的 app-header 底上"可辨但弱",
  2x 特写清晰、1x 正常视距偏淡。与既有消费者(ChatInput)观感一致,
  不在本轮调强;若后续真机复核觉得不足,应统一调 --shadow-ring 定义
  而非组件内各自加强。
- **新发现的存量问题(Button 任务输入)**:侧栏会话项(session-item)
  无 tabindex/role,键盘根本不可达——本任务的环帮不到它们;
  会话分组头(li tabindex)可达且有环。建议 Button 组件任务一并处理
  列表项语义(role="button"/roving tabindex)。
