## 1. memory 注入链路(现状)

- `app/src-tauri/src/memory/loader.rs:204` `load_for_session(cache, project_id, project_path)` — 固定 4 层序:User CLAUDE → User AGENTS → Project CLAUDE → Project AGENTS;read-through mtime fence(RULE-C-001,无 watcher)。
- `memory/file.rs:250` — 每层 load 时 `count_tokens(&body)`(cl100k,`memory/tokens.rs`)→ **`MemoryLayer.tokens` 每层 token 数现成**。
- `memory/loader.rs:293` `build_banner(layers)` — `<system>已加载 N 个 memory: [label] (X tokens)…</system>`;无 Loaded 层返回空串。
- `memory/loader.rs:349` `build_instructions_blocks(layers) -> Vec<ContentBlock>`:
  - Block 0 = banner,**唯一带 `cache_control: Ephemeral` 的块**(断点);
  - Block 1..N = 每层 body,AGENTS.md 包 `<primary instructions>`、CLAUDE.md 包 `<reference>`(B5 review §3 Q4 决策),不带 cache_control。
- `agent/chat_loop/init.rs:378-397` — **主注入点**(经典聊天 / 群聊参与者共用 `prepare_loop_state`):`load_for_session` → `build_instructions_blocks` → 合成 user(blocks)+ assistant("Understood…")对插在 messages 头部(pos 0/1);skill 列表插 pos 2。
- ⚠️ **第二个注入点(评审更正 08-15)**:`agent/subagent/prompt.rs:63` `build_worker_messages` — worker 有独立注入路径(dispatch 时构造 messages[0] memory 合成对 + 任务 append,自带独立 cache 断点)。**不是**所有路径都过 init.rs;WP1 度量与 WP2 gate 必须区分两条路径(见 design §3.5a)。
- `agent/system_prompt.rs:145` `assemble_system_prompt` — behavior prompt → mode prefix → base prompt,与 memory 相互独立(RULE-A-005:per-turn system 变化**不**打爆 memory 断点)。
- cache 语义:Anthropic 前缀缓存取**最长匹配断点**;memory 消息在会话最头,banner 断点保它之前(system)命中;body 变化只使其后失效。session 内 memory 内容固定(mtime fence)→ 天然前缀稳定。
- 群聊:`agent/group_chat_loop.rs:302/510` 把 memory_cache 传入同一 chat_loop 机制 → 注入同源。

## 3. C7D 可复刻模式(WP2 直接类比)

- `tools/stub.rs:33` `STUB_CANDIDATES: [&str; 10]` — 大 schema 工具候选集;`:89` `stubify(tools, loaded)`(未 loaded 的候选原地换 stub:真名 + 一句话摘要 + `{"type":"object"}` 外壳);`:105` `load_tool_schemas_def()` 元工具 def(**不进** `builtin_tools()`,侧挂 append);`:138` `StubRegistry`(session 粘性 loaded-set;`:168` `clear(session_id)`)。
- **执行路由(评审补)**:`load_tool_schemas` 不是普通注册工具——`agent/chat_loop/tools.rs:792-828` serial 顶部**按名拦截**(`if name == "load_tool_schemas"` → 读 registry 返回 schema 文本)。WP2 的 `load_memory_sections` 需同款拦截点 + `drive.rs:589` 侧挂 append。
- **registry 生命周期**:存储在 `state.rs:208`(`AppState.stub_loaded`,经典聊天共用);**清理点 = `commands/sessions.rs:363`**(delete_session 时 `stub_loaded.clear(&session_id)`);群聊路径每次新建独立 registry(`group_chat_loop.rs:350/558`),不走 AppState——digest registry v1 只服务经典聊天,挂 AppState + sessions.rs:363 同款即可。
- 开关:`agent/chat_loop.rs:613-618` — 每 request 读一次 `db::config::get_config_value(&db, "tools_stub_enabled")`,best-effort 缺省 on。
- gate:`drive.rs:537,589` `stub_on && !effective_is_worker && !is_group_chat`(worker 自主可靠性豁免;群聊白名单语义豁免)。
