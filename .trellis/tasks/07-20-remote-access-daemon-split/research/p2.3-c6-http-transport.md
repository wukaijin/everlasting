## 核心发现:args 字段命名 camelCase vs snake_case

**现状**:
- 前端 `streamController.ts:2185` `invoke("chat", { requestId, sessionId, messages })` —— **camelCase**。
- 这是 Tauri 2 的默认行为:`#[tauri::command]` 自动把 Rust snake_case 参数名暴露为 JS camelCase(`request_id` → `requestId`)。
- daemon handler 的 serde 默认 snake_case(`ChatRequest { request_id, session_id }`),**不做 camel 转换**。
- 直接透明转发 args 会字段全不匹配。

**design §3.2 "snake_case 统一" 假设与 Tauri 现实冲突**。

## 已采纳策略(C6 已实现于 `app/src/transport/http.ts`)

1. **args 顶层 key camel→snake**:`httpTransport.invoke` 把 args 的**顶层** key 转 snake(`requestId`→`request_id`),嵌套值(messages / struct)**原样透传**。
   - 理由:Tauri/daemon 对 Rust struct 用同一 serde(`db::types` / `llm::types`),前端读到的嵌套对象在两 transport 下字节一致;只有顶层 command 参数名需要扳正。
   - 实现:`camelToSnakeKey` + `transformArgsTopLevel`。
2. **返回值透传**:daemon 返回的 struct 与 Tauri 同 serde(同 Rust 类型),前端读法一致,无 transport 差异。**返回值方向无需转换**。
3. **agent.rs `ChatRequest` 保持 snake_case**(原本就对):httpTransport 把 `resendSeq`→`resend_seq`、`forcedDispatch`→`forced_dispatch`,daemon `ChatRequest.resend_seq` 匹配。**不需要给 ChatRequest 加 `#[serde(rename)]`**。
